# 3098N 协议与数据边界

## 有线 USB 输入

通过 Fn+6 切换前后的只读枚举对照，确认新增设备为 `320F:506A`、厂商 `AKKO`、产品 `AKKO Multi-modes Keyboard-N`。共六个 HID 集合，包含标准键盘集合和私有集合；监控仅被动接收归属于该型号的 Raw Input，不发送任何有线私有命令。有线电量读取协议尚未验证，不复用接收器命令。`320F:506B` 接收器仍插着并不表示当前输入来自 2.4G；输入来源按实际事件接口判断。旧版过滤规则未包含有线接口，历史标记中的“最近输入来源”可能只是较早的无线输入，无法追溯补采有线卡键。

## 2.4G 电量

已验证的型号标识为 `320F:506B`，私有接口 `MI_01/COL04` 的 usage page 为 `0xFF1C`，usage 为 `0x92`，Input/Output Report 均为 64 字节。

程序只发送一个固定电量读取命令：`04 20 00 1A 06` 后补零到 64 字节。请求字节 1–2 为请求体字节 3–63 的和，16 位小端。

已验证成功回复前缀：`04 20 00 1A 06 00 00 01`，字节 8 为设备上报百分比（0–100），字节 9 为含义未验证的状态原值。字节 1–2 回显请求值，不是整个回复的独立校验和。不提供任意命令、固件刷写、改键或配对写入接口。

依据来自官方管理器随附目标代码与已安装程序中读取函数的机器码核对，以及本机实际对照。此文档不包含原始二进制或反汇编。设备上报百分比不是经过容量校准的真实剩余能量；接线和未接线均见过状态原值 1，所以不将它解释为正在充电。

查询使用分开的 overlapped 读写句柄，先提交读，超时取消并等待取消完成，再释放缓冲区。不在系统独占键盘集合上发送私有命令。

## 蓝牙电量与设备识别

蓝牙标准电池服务为 `180F`，Battery Level 特征为 `2A19`。本项目曾在已连接设备上一次性 Uncached 读取核验百分比，并与 Windows 缓存比较一致。

常驻程序仅通过 cfgmgr32 读取绑定设备的 Windows PnP 字节属性 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5},2`。这是实测兼容属性，不是承诺跨版本稳定的公开电量接口；值缺失、类型错误或超过 100 均按不可用处理。缓存读取时间不是键盘测量时间。常驻程序不进行 GATT 服务发现、特征读写、CCCD 订阅或 MaintainConnection。

设备从 Windows 中名称匹配 `AKKO 3098 BT-1` 的蓝牙父节点发现；唯一候选可自动绑定，多候选需用户选择。地址只保存在当前用户的本机配置里，Raw Input 在入队之前按接收器型号或所选蓝牙身份过滤。

## 诊断边界

- 卡键时间是“首次按下到收到松开／观察中断”的按接口状态时长，不是精确物理故障时长。正常主动长按也可能触发。
- 电量查询超时不等于确定断联；休眠和迟到回复也可能超时。回复成功不等于输入已经恢复稳定。
- 蓝牙 ConnectionStatus 变化可能来自切换模式、关机、休眠或故障。观察时间不是精确射频变化时间。
- 当前没有 RSSI、无线重传次数、序列号，不能算无线丢包率；事件间隔也不是端到端延迟。
- USB 描述符的 `bInterval=1` 表示 Full-Speed 输入端点名义 1ms 调度，不代表每秒 1000 次有效键盘输入。
- USB 计时使用 UCX 的传输头和拓扑，不启用数据载荷。EP82 是共享端点，包含私有电量回复，不能当纯键盘报告流。
- 当前 ETW 拓扑解析只支持接收器直连根集线器；外部底座／集线器不支持此计时后端，其余监控可继续使用。
